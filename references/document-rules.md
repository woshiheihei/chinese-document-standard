# 字段与版本规则

用于选择通用默认。指定规范、接收方表单或既定受控流程要求优先。

## 哪些字段有用

| 字段 | 触发条件 | 写法 |
| --- | --- | --- |
| 作者或编制 | 需要署名、识别起草人、交接文档维护责任，或模板要求。 | 独立作品可写「作者」；协作中需要区分起草角色时用「编制」。 |
| 审核或复核 | 同行审阅、共同确认、规定的复核流程或要求留存复核结果。 | 写已核实的审核人、日期、结果。实际未审时按流程留空或标「待审核」。个人自查有追踪价值时可单独留记录。 |
| 批准 | 确有发布、执行、付款或生效的决定权，并且需要留存决定。 | 写实际批准人和批准日期。稿件需要跟踪决定且尚未批准时，标「待批准」。 |
| 封面与页码 | 封面能区分正式交付件或长文；两页以上可加页码。 | 封面写题名及必要元数据。分页文档的页码用字段生成。 |
| 目录 | 章节较多、需要跳读或按条查找。 | 分页文档按标题层级生成并更新；默认仅收一级标题。 |
| 附件与保密说明 | 有独立材料，或内容敏感、分享范围有约定。 | 用「附件 1 名称」的方式编号，正文首次引用给出名称。需要访问说明时写明允许查阅的范围。 |
| 文件编号、版本、修订记录 | 文件本身需长期维护、分发、交接或稳定引用，分别按实际用途启用。 | 编号识别文件，版本识别修改。文件名和正文中的版本写法保持一致。 |
| 生效日期、受控状态、分发记录 | 规则在特定日期执行，或需要追踪有效版本与接收范围。 | 仅记录可核实的日期、状态和接收范围。没有确认的日期不能用编稿日期代替。 |

通用日期采用 `YYYY-MM-DD`。记录表确实不适用的字段可写「不适用」；缺少实际数据时按用途标「待补」或留空。结论依赖某个时点时注明日期，依赖某一版本时注明版本。读者需要核对来源时，给出作者、联系方式或来源。

## 什么时候需要版本管理

- 一次性文件可用题名或题名加日期识别。持续维护且无既定编号规则时，从 V1.0 起。小改可升为 V1.1，结构或规则有较大变化时可升为 V2.0。
- 已共享的发布版应保留。更新时另存新版本；需记录修订时写日期、版本、变更内容和必要的修改人。记录依赖某版说明时，保留所使用的版本号。变更会影响正在使用文件的人时，应让相关人员知道版本有变化。
- 团队多人共用同一规则且用错版本会有实际后果时，再考虑有效版本目录、变更申请、分发记录和作废记录。单人日常文档可由作者自行核对和更新；不需要照搬受控流程。
